# Anki Template Engine

A zero-dependency (stdlib-only) Python module that turns compact card dicts
into a styled, tab-separated Anki import file via `build_deck(cards, output_path)`.
Output has three columns — front, back, and tags — with a `#tags column:3`
header. Every card must carry at least one tag (the subject); pass deck-wide
tags via `build_deck(cards, "deck.txt", tags=["rust", "unit-5-exam"])`,
merged with any per-card tags.

## Usage

```
./run.sh gen <cards.json>    # build a deck from a cards file, validate it, archive the input
./run.sh gen <driver.py>     # run a batch driver, validate every deck it wrote
./run.sh sample              # build the sample deck + self-check (smoke test)
./run.sh validate <deck.txt> # validate a generated deck file
```

The repo is the workspace: cards files (and any other source material) go in
the gitignored `input/` folder, generated decks go in the gitignored
`outbox/<batch>/` folder. After a `./run.sh gen` run in which every deck
validates, the inputs it consumed are auto-moved to `input/archive/<batch>/`
so the same source can't be regenerated by accident — move a file back into
`input/` to regenerate it. Paths passed to `run.sh` resolve against the
invoking directory.

Direct engine access:

```
python3 anki_templates.py --build cards.json -o deck.txt   # build from a cards file
python3 anki_templates.py                                  # build sample deck + self-check
python3 anki_templates.py --validate PATH                  # validate a deck file
python3 anki_templates.py --list-types                     # list available card types
```

## Cards files (the input format)

The normal input is a JSON file in the `anki-cards/1` format, written by
[anki-flashcard-generator](../anki-flashcard-generator):

```json
{
  "format": "anki-cards/1",
  "course": "Microbiology",
  "tags": ["microbiology", "unit-2-enzymes"],
  "cards": [
    {"type": "definition", "q": "What is a catalyst?", "a": "A substance that speeds a reaction without being consumed."},
    {"type": "key_list", "q": "Gram stain steps, in order?", "items": [["Primary stain", "crystal violet"], ["Mordant", "iodine"]], "ordered": true},
    {"type": "true_false", "q": "Enzymes are consumed by the reactions they catalyze.", "verdict": false, "a": "Catalysts are reused, not used up."}
  ]
}
```

`cards` are exactly the dicts `build_deck` takes; `tags` are the deck-wide
tags. Text fields are plain text: `load_cards()` HTML-escapes `& < >` on load,
so a cards file never contains markup (`*single asterisks*` around a term are
the engine's accent markup, not HTML, and pass through). `[label, desc]`
pairs are plain two-element lists.

```
python3 flashgen.py ... -o ~/Documents/CodeRepos/anki-template-engine/input/enzymes.json
./run.sh gen input/enzymes.json     # -> outbox/2026-09-11-enzymes/enzymes.txt
```

## Input checking

Every card is checked against `CARD_FIELDS` — the required and optional
fields per type — before it is built. A missing required field, or a field
the type's builder would not render, is an error naming the card rather than a
silently dropped field. `build_deck` also refuses two cards with the same
rendered front, since Anki matches imports on the first field and a duplicate
would overwrite a note. The output file is then checked by `validate_deck`
(headers, tab count, tags column, balanced HTML, no double `<br>`).

## Card authoring

See [INSTRUCTIONS.md](INSTRUCTIONS.md) for the universal card-authoring rules.
Its `> Version:` date is bumped on any meaningful content change, so downstream
batches can reference which instruction version produced them.

## Drivers

A driver is a Python script that builds a card list itself and calls
`build_deck` — the path for material that is not LLM-generated, such as a
glossary table (`gen_medterm.py`). A driver declares each source it reads
with `register_input(path)`, and `./run.sh gen driver.py` runs it, validates
what it wrote, and archives its inputs the same way.
